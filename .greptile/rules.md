# Requirements evidence and scope

Read the applicable owner-approved requirement manifest/specification identified by the PR and the referenced repository ADR sections. Do not substitute an unrelated specification, implementation behavior or a DRAFT for owner approval. Historical deferrals must be distinguished from later explicitly authorized scope.

When supplying requirements analysis, report each applicable ID with authoritative source/section, exact implementation line, named test and any actually observed execution evidence, PASS/FAIL/UNVERIFIED/NOT APPLICABLE, and actionable severity. Do not claim tests ran unless your tools actually executed them. Missing evidence is UNVERIFIED, not PASS. A confidence score or zero comments does not certify requirements coverage.

If a full requirements matrix or approved source is unavailable, state that limitation explicitly; a separate independent requirements assessment is mandatory under the owner-adopted policy. Keep that assessment attributed to its actual reviewer. Report genuine defects without promoting explicitly deferred work into this PR.

Read docs/REVIEW_POLICY.md and verify its activation receipt and PR eligibility; these rules do not activate the policy or waive current gates. No automatic merges, main/force pushes or deployments are authorized.

## Context

Following the implementation and acceptance of the pure mathematical unwinnability proof engine prototype in `@chess-platform/core` ([ADR 0168](0168-general-unwinnability-analysis-prototype.md)), the platform required a concrete domain integration model for FIDE Article 5.2.2 dead-position adjudication.

Independent reviews (`work/pi124-live-integration-path/final.txt` and `work/opencode124d-domain-contract-review/final.txt`) identified key architectural hazards in naive integration paths:
1. **Queue Blockage**: Running expensive cooperative helpmate BFS directly inside synchronous WebSocket authority message handlers would stall the gateway event loop, degrading latency for all games on that instance.
2. **Clock and Lease Drift**: Suspending a game during adjudication without exact anchor arithmetic could cause clock distortion, double increment credits, or spurious timeout forfeits.
3. **Partial Prefix Vulnerabilities**: Committing a partial adjudication resolution without atomic effect execution could leave games permanently stuck or corrupt historical replay.
4. **Forged Evidence & Insecure Oracles**: Accepting arbitrary caller-provided Boolean flags or structural proof objects would compromise rules integrity.

Root technical direction authorized a strictly bounded **Stage 1 (Domain/Reader Preparation)**. This stage establishes the pure domain-owned prepared-command boundary, the deterministic adjudication lifecycle state machine, pause/resume clock arithmetic, and reader-level compatibility protections. Live writer emission, transactional leasing, background worker scheduling, and client pending presentation remain strictly deferred and on HOLD until subsequent stages.

## Decision

Implement the pure prepared-command and adjudication domain lifecycle in `@chess-platform/game`, update persistence and gateway readers for stream safety, and enforce zero live emission.

### 1. Four Discrete Aggregate Lifecycle Phases

The `Game` aggregate transitions deterministically across four phases:

| Phase | Description | Allowed Next Event | Command Execution |
|---|---|---|---|
| `idle` | Normal gameplay | Existing game events or matching `AdjudicationStarted` | Playable under existing rules |
| `proving` | Command held; awaiting proof resolution | Matching `AdjudicationResolved` | Blocked (`isBlocked === true`, commands reject) |
| `settling` | Resolution admitted; awaiting declared effects | Exact next declared effect matching cursor | Blocked (`isBlocked === true`, commands reject) |
| `ended` | Terminal game state | None | Terminal (`status.over === true`) |

While in `proving` or `settling` (`game.isBlocked === true`):
- All ordinary command entry points (`playMove`, `resign`, `offerDraw`, `acceptDraw`, `declineDraw`, `claimFlag`, `abort`, `markReady`, `expireNoShow`) immediately throw `GameError('Cannot execute command while adjudication is pending')`.
- `flagDeadline` evaluates to `null`.
- `timeoutDue(...)` evaluates to `false`.
- `noShowVerdict(...)` evaluates to `{ kind: 'not_due' }` (preserving existing union contract without synthetic variants).

### 2. Exact Declared Effect Plan and Append Batch Validation

`AdjudicationResolved` carries an exact, bounded array of declared effect events generated by the domain settlement builder (`settlePrepared`), never arbitrary caller input:
- **Move intent**: `MovePlayed`, optionally followed by `GameEnded` (checkmate, stalemate, insufficient material, 50-move, 3-fold repetition, or successor dead position).
- **Resignation intent**: `GameEnded(resignation)`.
- **Draw negotiation**: `DrawOffered` or `DrawDeclined` or `GameEnded(agreement)`.
- **Readiness intent**: `PlayerReady`, or a verified zero-effect continuation.
- **Timeout expiry**: `GameEnded(timeout)` if winnable, or `GameEnded(insufficient_material)` if impossible.
- **Predecessor dead position**: `GameEnded(dead_position)` immediately, discarding held move intent.
- **Creation admission**: zero effects (or `GameEnded(dead_position)` if initial position is dead).

**Separation of Folding from Append Validation**:
- **Prefix Replay (`Game.fromEvents`, `withEvents`, `replayStoredHistory`)**: Prefix-tolerant. Replaying `[Started, Resolved]` leaves the aggregate in the blocked `settling` phase waiting for effects.
- **Append Batch Validation (`validateAdjudicationAppendBatch`)**: A proposed append batch may end in `proving`, but must NEVER end in `settling`. An `AdjudicationResolved` event and all its declared effects must be committed in the exact same atomic transaction batch.
- **Shared Path Replay Enforcement**: Shared lifecycle and effect validation runs on the unified path used by both `Game.reduce` and `Game[FOLD_STORED]`, ensuring that forbidden moves are caught before `admit` or `onPly` callbacks fire.

### 3. Event Sequence and Revision Binding

The domain aggregate privately tracks the exact count of folded events (`eventSequence`). The lifecycle strictly binds:
- `AdjudicationStarted.baseRevision == preceding eventSequence`
- `AdjudicationResolved.startedSeq == actual AdjudicationStarted sequence`
- Replay verifies exact agreement of `gameId`, `operationId`, `baseFen`, `variant`, and `rulesVersion`. Backward timestamps ($R < A$) are strictly rejected.

### 4. Cheap Command Admission Preflight

Existing `Game` command methods tentatively settle games immediately, which makes them unsuitable for pre-proof holding. A dedicated preflight module (`packages/game/src/prepared-command.ts`) extracts cheap admission before expensive proof or clock freeze:
- `prepareMove`: verifies turn, parses UCI, constructs SAN and successor FEN, checks legality without settling terminal outcomes.
- `prepareResign`, `prepareDrawOffer`, `prepareDrawAccept`, `prepareDrawDecline`, `prepareAbort`: validate prerequisites.
- `prepareReady`: distinguishes meaningful readiness effects from no-ops.
- `prepareFlagExpiry`, `prepareNoShowExpiry`: validate due deadlines.
- `prepareCreationAdmission`: validates initial position parameters.

All prepared operations are defensively cloned to prevent input or returned mutation tampering.

### 5. Process-Local Opaque Evidence Adapter and Recorded Proof Schema

To guarantee proof authenticity without exposing raw engine internals or trusting structural caller objects:
- `packages/game/src/adjudication-proof.ts` maintains a module-private `WeakMap<object, VerifiedEvidenceRecord>` registry.
- Evidence handles (`AdjudicationEvidenceHandle`) are minted ONLY from internally invoked core proof executions (`analyzeDeadPosition`, `analyzeWinnability`).
- Positive mate witnesses undergo canonical legal replay verification through checkmate (`verifyWitnessReplay`).
- Settlement rejects literal objects, spread clones, JSON deserialized objects, and cross-operation handle reuse.
- Persisted event logs store structured JSON outcome metadata (`RecordedResolutionEvidence` containing `RecordedGlobalOutcome`, `RecordedImpossible`, or `RecordedReachable`).
- On replay and append batch validation, recorded evidence is validated: positive witnesses must replay canonically to checkmate (`verifyUciWitnessReplay`), dead outcomes must certify both white and black impossibility with valid provenance (`static_certificate`, `closed_graph`, or `closed_graph_material_pruned`), and every non-terminal lifecycle continuation (`creationAdmission`, `ready`, `expireNoShow`, `abort`, `move`, `expireFlag`) requires and validates global base evidence unless cheap root precedence applies. Validated global-dead base evidence short-circuits unused successor and directional timeout roles. Replay is pure and deterministic, evaluating cheap status precedence (`Position.status()`, `isFrozenDeadPosition()`, threefold repetition) without invoking the general static mobility solver (`computeMobility`).
- Neither live settlement nor historical replay trusts caller-declared effect events: the domain independently derives the deterministic plan (`deriveResolutionPlan`), verifies field-for-field equality, and executes deep-cloned, immutable derived effects with frozen clock balances.
- **State Encapsulation & Repetition Map Privacy**: The authoritative native repetition Map is private to the `Game` instance. `Game.prototype.snapshot()` returns a fresh detached Map on each access, ensuring that caller mutations (including `Map.prototype.set.call` bypasses) cannot corrupt internal state or cause false threefold draws.
- **Ingress and Egress TimeControl & Retained Record Ownership**: `timeControl` is deep-cloned and frozen at ingress (`Game.create` params and `reduceGameCreated` replay events) and egress (`snapshot()`, `game.timeControl` getter). Adjacent plain-value records (`players`, `status`, `moves` with nested balances, and `clock`) are deeply frozen and isolated.
- **Canonical No-Show Nested Timestamp Enforcement**: `assertStartedNoShowEnding` enforces full canonical verdict metadata equality, verifying `ending.at === verdictEnding.at` alongside result, termination, and winner.

### 6. Clock Representation and Pause/Resume Math

The domain retains the established `ClockState` data structure without adding speculative union variants:
- `PendingAdjudicationState` records `originalClock`, suspension instant $A$, thinking elapsed at $A$, and remaining no-show time.
- **Clock Freeze**: Balances are frozen with `turnStartedAt = null` throughout both `proving` and `settling`. `charge()` is NOT called during freeze, preventing improper Fischer increment credits.
- **Same-Turn Resume**: Restores original balances and shifts the turn anchor:
  $$\text{resumedAnchor} = \text{originalAnchor} + (R - A)$$
- **Held Move Execution**: Charges the original balances using recorded $\text{elapsed}_A$ once, with `MovePlayed.at = R`, granting exactly one increment. The opponent's clock anchor begins at $R$.
- **Timestamp Bounds and Active Causal Basis**: Enforces safe integer bounds $\le 8,640,000,000,000,000$ ms across all arithmetic derivations. Suspension instant $A$ is checked against the active causal basis:
  $$\text{activeCausalBasis} = \max(\text{createdAt}, \text{turnStartedAt}, \text{lastMoveAt}, \text{lastResolutionAt})$$
  Rejecting backdated suspension ($A < \text{activeCausalBasis}$) across null-anchor and managed settlement states.
- **Surviving Obligations Atomicity and Projection**: Pure projection of final terminal state, ply, and readiness from derived effects (`projectSurvivingObligations`) shared across plan validation (`deriveResolutionPlan`), settling completion (`Game.advanceSettlingNonMove`), and zero-effect continuation (`reduceAdjudicationResolved`). Tournament games where both players are ready (including when the selected `PlayerReady` supplies the second seat) are exempt from no-show deadlines and retain safe historical `noShowAt` without calculating or validating unused overflowing additions ($R + \text{remaining}$). Active seek and missing-readiness tournament games strictly reject real overflow atomically.
- **Decoupled Timestamp and Fractional Deadline Validation**: Injected lifecycle timestamps $A$ and $R$ ($R \ge A$) are strictly validated as non-negative safe integers within Date bounds (`validateTimestamp`), while derived flag deadlines are validated as finite non-negative numbers within Date bounds (`validateDeadline`). This preserves raw fractional balances (e.g. initial 1000.5, inc 0.25), flagDeadline 3000.5, and whole-millisecond timeoutDue boundaries without rounding stored state.

### 7. Pure Authoritative Admission & Legitimate No-Ops

To prepare for future authority integration without altering legacy direct methods:
- **Authoritative Command Selector (`prepareAuthoritativeCommand`)**: Evaluates canonical arbitration ordering: due no-show forfeit, then due running flag expiry, then requested command (move, resign, offerDraw, acceptDraw, declineDraw, abort, ready). If a move is requested while the mover's clock is expired, it is normalized to flag expiry rather than producing an illegal-move error. Wrong flagged side is refused.
- **Legitimate Readiness No-Ops (`prepareReady`, `classifyReadyNoop`)**: Distinguishes actionable readiness from legitimate no-ops (`unsourced`, `post_first_move`, `already_ready`, `late`, `game_over`). Actionable ready returns `PreparedOperation & { kind: 'prepared' }`; legitimate no-op returns `{ kind: 'noop', reason: ReadyNoopReason }` without issuing `AdjudicationStarted` or proof obligations. Unknown discriminants throw `GameError`.
- **Semantic Tournament First-Move Admission**: Aligns `assertStartedMoveReadiness` with `prepareMove` and `checkStateNoShowVerdict`: both-ready tournament first moves after historical deadlines are admitted, while equivalent seek games correctly normalize to no-show expiry.

### 8. Reader-Only Adaptations

Minimal, non-intrusive reader protections ensure system stability:
- `packages/persistence/src/games-projection.ts`: Streams containing lifecycle events (`AdjudicationStarted` or `AdjudicationResolved`) are validated via `Game.fromEvents` to guarantee exact domain parity for plan derivation, SAN, and clock balances, while streams without lifecycle events preserve the existing fast fold for pre-127 Atomic compatibility. Complete committed streams ending in incomplete settling state are rejected with `CorruptGameStreamError`.
- `packages/realtime-gateway/src/authority.ts`: `toBroadcast` and `viewOf` project `legalMoves: {}` when `game.isBlocked` is true.

## Scope and Boundaries

- **Zero Live Writer Emission**: The gateway authority does NOT emit `AdjudicationStarted` or `AdjudicationResolved` in live play during Stage 1.
- **Zero Schema Migrations / Database Changes**: No new SQL tables, migrations, or database columns are introduced.
- **Zero New Dependencies**: No external npm packages or network services added.
- **Code Health Standards**: All new production helpers strictly adhere to:
  - $\le 4$ parameters
  - Own-function decision complexity $\le 10$
  - Nesting depth $\le 5$
  - Zero `as any` type assertions across all modules.
